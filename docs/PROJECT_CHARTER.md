# RCSL 项目宪章：人类判断、证据与责任

[English](PROJECT_CHARTER_EN.md) · [能力模型](COMPETENCY_MODEL.md) · [收口后的路线图](DUAL_MODE_ROADMAP.md)

## 我们为何存在

Research Code Stewardship Lab 的出发点不是让人或 Agent 更快地产出“能跑”的代码，而是训练并支持人类判断：实现是否忠实于研究问题，实验是否公平，证据是否足以支撑主张，以及 Agent 是否始终处于被批准的边界内。

仓库后来有意形成两个核心闭环，但责任中心没有改变：

1. **Mode Audit**：帮助研究负责人审计真实研究代码，保存可复核的证据和人工决定；
2. **Mode Train**：让学习者与独立审阅者围绕同一份冻结材料练习识别、证明、处置和沟通风险。

发布、分包、页面、Registry、托管和集成都只能是服务这两个闭环的辅助能力，不能成为第三条产品主轴。

## 长期信条

> **能跑不等于可信。Agent 可以执行，人必须判断。主张必须回到证据，状态词不得超出保证。先闭环，再平台；先试点，再扩张；先剪枝，再新增。**

1. **人类保留最终责任。** Agent 可以搜索、实现、检查和整理，但研究范围、风险接受、证据充分性、发布与停止决定必须由具名人类作出。
2. **研究忠实度优先于表面可运行性。** 测试通过、脚本执行成功或记录自洽，都不能代替对算法语义、流水线完整性、科学有效性和 Agent 治理的判断。
3. **证据先于状态。** finding、review 和 decision 必须绑定审阅者实际看到的 case、artifact 或 attempt；自由文本引用不能伪装成内容证据。
4. **冻结对象必须一致。** 学习者、审阅者和审计负责人必须能确认自己讨论的是同一版本、同一字节和同一人工决定。
5. **自动检查只声明其真实边界。** 结构检查、本地 hash chain、preflight 和声明式 `verified` / `closed` 都不得描述成科学证明、身份认证或独立复现。
6. **L1–L4 是失效层，不是人的全部能力。** G0、研究判断、快速分诊、委派与 Agent 保障、架构维护、安全隐私伦理、事故响应和证据沟通共同组成完整训练框架；系统不自动替人给这些能力打分。
7. **默认采用最小权限与最少暴露。** 本地优先、显式输入、明确授权；不隐式执行项目、不联网、不读取受保护材料，也不采集与当前决定无关的数据。
8. **真实使用先于产品扩张。** 合成测试只能支持 `internally verified`。没有真实项目、真实人员、观察记录和失败案例，就不能宣称 `field validated`，也不能以“平台感”为理由建设新表面。
9. **复杂度必须有用户回报。** 每一层 schema、锁、发布契约或安全防护都必须解除已观察到的核心阻塞；通用认证、托管、远程运营和同权限恶意进程防护需要独立的部署边界与负责人。
10. **可删除性是设计要求。** 新能力必须写明非目标、退出条件和维护责任；一旦不再服务核心闭环，应冻结、拆出或删除，而不是靠更多兼容层维持。

## 每项工作开始前的防偏移决策门

任何 issue、计划、PR 或 Agent 任务都必须先回答：

1. 它直接服务哪一个核心用户：Audit 负责人，还是 Training 学习者/审阅者？
2. 它解除的是哪个已经观察到的阻塞？证据是什么？
3. 它如何增强而不是替代人的判断、复核或责任？
4. 它绑定了哪些真实对象和字节？哪些内容仍只是声明？
5. 最小可交付切片是什么？明确不做什么？
6. 成功最多能提升到 `implemented`、`internally verified`、`field validated` 还是 `production ready`？依据是什么？
7. 如果试点证明它无用，何时冻结或删除？由谁维护？

只要第 1–5 项没有清楚答案，工作就不得进入核心。仅仅增加测试数、页面、Registry、集成、通用抽象或防护层，不构成立项理由。

## 当前长期推进顺序

1. 收口 Audit 的 G0、工作区边界、失败恢复与诚实状态词；
2. 让 Audit case 与 evidence 绑定真实 Git revision、合约和 artifact bytes；
3. 让 Training case、attempt、rubric 与 reviewer packet 绑定同一份冻结材料；
4. 完成一次第二人可独立复核的真实 Audit；
5. 完成一次真实学习者—独立审阅者试点；
6. 只根据试点暴露的阻塞，决定是否恢复 Phase 3B 或 Phase 4。

在前两类真实试点完成前，Phase 3A 只维护不扩张；Phase 3B、展示、Dashboard、Registry 和托管继续冻结。

## 停止条件

出现以下任一情况时，停止实现并重新审查方向：

- 功能不能直接改善两个核心闭环中的任何一个；
- 自动状态开始替代人类对证据充分性或科学主张的判断；
- 支撑模块的复杂度再次超过其服务的核心流程；
- 为了“未来也许会需要”而引入远程服务、认证、数据库、UI 或通用插件层；
- 合成测试被用来宣称真实训练有效、真实审计成功或生产安全；
- 工作需要读取、分发或推断受保护材料，却没有新的明确授权与责任边界。

本宪章优先于阶段编号和既有路线图。路线可以调整；“人类判断、可复核证据与最终责任”不能被调整掉。
